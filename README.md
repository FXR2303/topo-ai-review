# TOPO AI — 3D 模型拓扑质量评测平台

TOPO AI 是一个面向游戏美术、3D 资产审核与外包验收场景的模型质量评测工具。它把低模检查、高低模烘焙贴合、人工评分、问题标注、模型归档、模型 PK 和数据分析整合到同一套工作流中。

## 产品思考

传统模型评审经常分散在截图、聊天记录和口头反馈中，存在三个问题：

1. **标准不统一**：不同评测人关注点和评分尺度不一致。
2. **证据难追溯**：问题位置、模型版本、评分理由容易丢失。
3. **自动检测容易越权**：工具给出的几何风险可能被误当成最终是否通过的结论。

因此，本项目把“机器发现风险”和“人工做最终决定”明确分开：

- 自动预检只输出 **提醒** 或 **严重**，用于定位开放边、非流形、退化面、长细面、高连接顶点和 UV 覆盖风险。
- 是否通过必须由评测人手动选择，自动结果和综合分数都不能替代人工结论。
- 每项评分要求附带证据，模型表面标注、问题分类和总结性建议会一起进入评测档案与报告。

## 评测标准

总分为 100 分，由六个维度加权计算：

| 维度 | 权重 | 判断重点 |
| --- | ---: | --- |
| 形体与轮廓 | 25% | 比例、体块与特征是否准确 |
| 拓扑正确性 | 20% | 穿插、破面、非流形和开放边 |
| 布线结构合理性 | 15% | 面流是否服务形体和变形 |
| 布线细节控制 | 10% | 曲面、锐边与转折是否清晰 |
| 密度与低模效率 | 10% | 面数是否集中在有效区域 |
| 高低模贴合与烘焙 | 20% | 法线、接缝、笼子与包裹风险 |

## 核心功能

- 导入低模 OBJ，并可选导入高模 OBJ。
- 3D 旋转、缩放、预设视角、着色模式和“着色 + 拓扑线框”模式。
- 模型表面点击标注，可记录提醒/严重等级和问题说明。
- 高低模烘焙贴合模拟：蓝色表示可成功包裹，红色表示露出或包裹失败区域，并显示成功率与失败面数量。
- OBJ 网格自动预检：开放边、非流形、退化面、长细面、高连接顶点和 UV 覆盖。
- 六维加权评分、证据记录、问题标签和人工通过/不通过。
- 草稿保存、正式入库、搜索筛选、详情查看和模型悬浮预览。
- HTML、JSON 评测报告导出及打印/保存 PDF。
- 模型 PK：A/B 两侧可分别独立导入 OBJ，统一视角比较并保存人工结论。
- 数据分析：评测数量、通过率、平均分、问题分布和模型排行。

## AI 工具与协作方式

本项目主要使用 **ChatGPT / Codex** 辅助完成产品定义、代码实现和测试。

AI 在开发中的具体作用：

- 根据完整需求聊天记录和四张产品截图，重建页面结构、视觉层级与交互流程。
- 协助把“好不好看”转化为可执行的六维评测标准和权重。
- 生成 React、Three.js、Cloudflare D1/R2 相关代码，并持续做代码检查和构建验证。
- 根据反馈迭代交互，例如高模导入选填、全页模型预览、模型表面标注、模型库悬浮预览和 PK 独立导入。
- 生成闭合低模、局部包裹失败高模和开放边故障低模，用于完整回归测试。
- 在测试中发现并修复 OBJ 非索引顶点重复统计、无 WebGL 时指标未计算、重新导入后旧状态残留、草稿重复入库等问题。

人的主要职责：

- 定义真实的 3D 美术评测场景和关键工作流。
- 校正 AI 对 Substance 3D Painter / Marmoset Toolbag 烘焙贴合表现的理解。
- 决定评分维度、自动检测权限边界和最终验收规则。
- 逐轮检查产品是否符合实际模型评测习惯。

## 开发过程

1. **需求还原**

   从聊天记录和页面截图中整理四个模块：模型评测、模型库、模型 PK、数据分析。

2. **建立评测规则**

   先定义评分维度、权重、证据字段和人工判定原则，再实现界面，避免只复刻视觉而缺少可用标准。

3. **实现 3D 检查能力**

   使用 Three.js 加载 OBJ，计算网格指标，并实现着色线框、模型标注和高低模包裹覆盖检查。

4. **加入持久化**

   使用 Cloudflare D1 保存评测与 PK 结果，使用 R2 保存用户导入的模型文件。

5. **完整流程回归**

   使用专门生成的高低模测试对走完导入、预检、贴合、标注、评分、人工判定、报告、入库、悬浮预览和 PK 流程。

6. **发布**

   完成 ESLint、生产构建与部署检查后发布公开版本。

## 回归测试结果

- 闭合低模：100 顶点、196 三角面，开放边为 0。
- 混合高模：贴合成功率 97%，检测到 6 个烘焙失败面。
- 开放边故障低模：检测到 4 条开放边并标记为“严重”。
- 严重预检结果不会自动否决模型，人工仍可独立选择通过或不通过。
- 草稿和正式入库更新同一条记录，不会生成重复档案。
- PK 的 A/B 两侧可分别导入 OBJ，人工结论能够持久化保存。

## 当前限制

- 当前主要支持 OBJ；接口已预留 GLB/GLTF 文件上传类型，但 3D 评测流程以 OBJ 为主。
- 烘焙贴合是用于评审的几何覆盖模拟，不生成最终法线贴图，不能完全替代 Substance 3D Painter 或 Marmoset Toolbag 的正式 Bake。
- 大型模型的浏览器端几何检测性能取决于设备 GPU、内存和 WebGL 支持。
